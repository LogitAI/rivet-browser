# SPEC

모든 항목은 `Draft`에서 시작한다. 소유자가 `Agreed`로 바꾸고, 수용 기준이 검증되면 `Done`으로
바꾼다.

## 1. 기능 요구사항

### FR-1 로컬 브라우저 세션 (`Agreed`)

Rivet은 사용자가 고른 설치된 Chromium 브라우저와 프로필을 찾아 세션을 시작, 조회, 종료한다.

- 수용 기준: 지원하는 브라우저를 찾지 못하면 실행 파일을 추측하지 않고 이유와 설정 방법을 보고한다.
- 수용 기준: 세션 종료는 Rivet이 시작한 창과 자식 프로세스만 닫고 사용자가 별도로 연 브라우저 창은
  닫지 않는다.
- 수용 기준: 런처는 Chrome, Edge, Brave, Whale, Samsung Internet을 보여 주고 App Paths에 등록된
  브라우저만 고를 수 있게 한다.
- 수용 기준: 세션 창은 소유 창이 없고 크기 조절 프레임이 있는 브라우저 최상위 창만 고른다. 같은 순간에 뜬
  알림이나 다른 창을 세션으로 잡지 않는다.

### FR-2 직접 프레임 통합 (`Agreed`)

Rivet은 Windows에서 실제 브라우저 app window 안에 Rivet 프레임을 직접 통합한다. 웹 콘텐츠는 실제
브라우저가 렌더링한다.

- 수용 기준: 지원 브라우저와 버전에서 Rivet 사이드바와 명령 바가 보이고 기본 탭바와 주소 표시 영역이
  사용자 작업 공간을 차지하지 않는다.
- 수용 기준: 창 크기 변경, DPI 변경, 최소화, 복원, 포커스, IME 입력이 Rivet 프레임과 웹 콘텐츠에
  일관되게 적용된다. 실제 Windows 확인 목록으로 검증한다.
- 수용 기준: Rivet은 별도 최상위 창을 만들지 않고 브라우저 창을 다른 창의 자식으로 옮기지 않으며 전체화면을
  요구하지 않는다. 캡션 버튼은 브라우저의 한 벌만 보인다.
- 수용 기준: 브라우저는 웹 콘텐츠를 사이드바 옆에 배치한다. 클라이언트 왼쪽에서 콘텐츠까지의 거리가 사이드바
  폭과 1픽셀 이내로 같고, 실제 클릭이 의도한 링크에 들어간다. `scripts/tests/windows-frame.ps1`로 검사한다.
- 수용 기준: 사이드바는 브라우저가 실제로 배치한 배율을 따른다. 배율이 다른 모니터로 옮겨도 폭이 어긋나지
  않고, 창의 위쪽 테두리 아래에서 브라우저 타이틀바와 같은 높이로 시작한다.
- 수용 기준: 브라우저가 전체화면이면 사이드바는 빠지고, 전체화면을 나오면 돌아온다.
- 수용 기준: Rivet 창은 작업 표시줄에서 Rivet 아이콘으로 브라우저와 따로 묶인다.

### FR-3 작업 공간과 탭 (`Draft`)

Rivet은 Appbar에서 스페이스와 탭을 관리하고 복원한다.

- 수용 기준: 스페이스마다 이름, 색, 기반 브라우저, 프로필을 정할 수 있다. 스페이스를 바꾸면 그 스페이스의
  브라우저와 프로필로 바뀌고, 프레임과 강조색이 그 스페이스 색을 따른다.
- 수용 기준: 탭 목록은 고정 탭, 폴더, 오늘 탭으로 나뉜다. 고정하지 않은 탭은 기본 12시간 뒤 보관되고 기간은
  설정에서 바꿀 수 있다.
- 수용 기준: 링크와 새 창으로 열리는 링크는 현재 스페이스의 새 탭으로 열린다. 탭이나 링크를 길게 누르면 링크
  미리보기로 열린다.
- 수용 기준: 선택된 탭을 닫으면 바로 아래 탭이 선택되고, 아래 탭이 없으면 위 탭이 선택된다. Ctrl+Shift+T는
  닫은 탭을 같은 자리에 되살린다.
- 수용 기준: Ctrl+T가 명령 바를 열지 새 탭 페이지를 열지 설정에서 고를 수 있다.
- 수용 기준: Appbar의 폭은 200에서 420 DIP 사이로 끌어서 바꾸고, 숨기면 창 왼쪽 끝에서 꺼내 볼 수 있다.
- 수용 기준: 작업 공간을 바꾸면 해당 작업 공간의 페이지가 보이고, 돌아오면 URL, 제목, 순서가 복원된다.
- 수용 기준: 브라우저가 종료되거나 업데이트된 뒤에도 Rivet이 저장한 작업 공간 데이터가 손상되지 않는다.

### FR-4 CLI 제어 (`Agreed`)

`rivet` CLI는 세션, 페이지, 탐색, 입력, 읽기, 작업 공간을 제어하는 기계 판독 가능한 명령을 제공한다.

- 수용 기준: CLI는 사람이 읽는 출력과 명시적으로 선택한 JSON 출력을 모두 제공한다.
- 수용 기준: CLI가 만든 페이지와 프레임에서 연 페이지는 같은 Rivet 작업 공간 상태로 보인다.

### FR-5 표시 정책 (`Agreed`)

CLI와 API는 브라우저 작업마다 `visible`, `hidden`, `auto` 표시 정책을 받는다.

- 수용 기준: `visible`은 사용자가 보는 브라우저 창과, 요청하면 시각 자동화용 프레임을 제공한다.
- 수용 기준: `hidden`은 보이는 창과 프레임 캡처를 만들지 않지만 탐색, DOM, JavaScript, 다운로드 정책은
  브라우저에서 계속 실행한다.
- 수용 기준: 시각 증거가 필요한 명령이 `hidden`에서 실행되면 `auto`는 표시를 만들고, `hidden`은
  실패 이유나 필요한 승격을 보고한다.

### FR-6 Ember 설정과 작업 공간 (`Draft`)

Ember 서버는 사용자별 Rivet 설정 문서와 논리 작업 공간을 보관한다. 등록된 Rivet 클라이언트는 이를
가져와 적용한다.

- 수용 기준: 한 클라이언트에서 저장한 사이드바 설정과 작업 공간이 다른 등록 클라이언트에서 사용자
  확인 뒤 적용된다.
- 수용 기준: 서버 또는 네트워크 장애 중에는 마지막으로 검증한 로컬 설정을 쓰고, 다시 연결되면 충돌을
  사용자에게 보여 준다.
- 수용 기준: 동기화 데이터에 쿠키, 비밀번호, 패스키, 브라우저 암호화 키가 포함되지 않는다.

### FR-7 Ember 컴퓨터 egress (`Draft`)

Ember가 프로젝트나 세션의 컴퓨터를 고르면 Rivet은 그 컴퓨터에서 브라우저 요청을 실행할 수 있다.

- 수용 기준: 선택된 컴퓨터의 외부 IP 확인 페이지가 그 컴퓨터의 egress를 보인다.
- 수용 기준: 대상 컴퓨터가 오프라인이면 직접 연결로 조용히 대체하지 않고 명시적으로 실패한다.

### FR-8 설치와 업데이트 (`Draft`)

Rivet은 DSA의 WiX 기반 설치 흐름을 Rivet 패키지에 맞춰 사용한다.

- 수용 기준: 설치, 업그레이드, 제거가 Rust 바이너리와 Rivet 설정을 각각 문서화한 정책대로 처리한다.
- 수용 기준: 설치와 업데이트는 서명과 해시가 맞는 Rivet 배포물만 적용한다.

### FR-9 분할 보기와 미니 창 (`Draft`)

Rivet은 한 창에서 여러 페이지를 나란히 보여 주고, 페이지를 미니 창으로 띄운다.

- 수용 기준: 탭이나 미니 창을 페이지의 위, 아래, 왼쪽, 오른쪽 가장자리에 놓으면 그 페이지가 그 방향으로
  나뉜다. 한 창에 최대 네 페이지까지 그리드로 배치한다.
- 수용 기준: 분할된 각 페이지는 둥근 모서리의 별도 패널이고, 작업 중인 패널은 강조색 테두리 없이 그림자로
  구분한다.
- 수용 기준: 분할된 페이지를 손잡이로 끌어 페이지 밖에 놓거나 미니 창 버튼을 누르면 미니 창이 된다. 미니 창을
  다시 페이지에 놓으면 같은 탭으로 돌아온다.
- 수용 기준: 캡션 버튼은 창 오른쪽 위 모서리의 페이지에만 있고 Windows가 그리는 버튼을 그대로 쓴다.

### FR-10 Sidebar (`Draft`)

Rivet은 창 오른쪽에 확장 프로그램 Sidebar를 둔다.

- 수용 기준: Sidebar는 캡션 버튼이 있는 페이지의 주소 줄 아래에 붙고, 주소 줄과 캡션 버튼의 위치를 바꾸지
  않는다.
- 수용 기준: 확장 패널은 웹 공간을 덮지 않고, 열리는 만큼 웹 페이지 영역이 좁아진다.
- 수용 기준: Sidebar는 접힌 상태로 시작한다. 접힌 동안 열기 버튼은 보이지 않고, 창 오른쪽 아래 모서리에
  포인터가 오면 반투명으로 나타난다.

### FR-11 개발자 모드 (`Draft`)

Rivet은 탭마다 개발자 모드를 켜고 끈다.

- 수용 기준: `localhost`, `127.0.0.1`, `[::1]` 페이지는 개발자 모드로 시작한다. 다른 페이지는 사용자가 켠다.
- 수용 기준: 개발자 모드인 페이지의 주소 줄은 다른 배경과 고정폭 주소로 구분되고, 캡션 버튼 왼쪽에 링크 복사,
  미니 창으로 열기, 스크린샷, 요소 검사, 콘솔, 네트워크, 성능 버튼을 둔다.

## 2. 비기능 요구사항

### NFR-1 브라우저 소유권 (`Draft`)

Rivet은 Chromium 소스를 포크, 수정, 재배포하지 않는다. 실제 페이지 렌더링에 웹뷰를 쓰지 않는다.

### NFR-2 보안 경계 (`Draft`)

Rivet과 Ember는 브라우저 비밀번호 저장소, 패스키 비밀값, 쿠키 데이터베이스, 운영체제 암호화 키를
복사하거나 원격 전송하지 않는다.

### NFR-3 호환성 (`Draft`)

직접 통합은 지원하는 브라우저와 버전을 공개하고, 각 지원 조합에서 창, 입력, 프레임, CLI 회귀 검사를
통과해야 한다.

- 수용 기준: 지원 빌드 표에 없는 빌드에서는 런타임이 브라우저 코드를 바꾸지 않고, 브라우저는 평소처럼
  동작한다.
- 수용 기준: Rivet은 브라우저 업데이트를 막거나 늦추지 않는다.
- 수용 기준: 정기 CI가 새 Chrome Stable 빌드를 공개 심볼로 표에 추가하고, 실제 브라우저에서 프레임 검사를
  통과한 경우에만 pull request를 연다.

### NFR-4 배포 (`Draft`)

Windows 설치기와 업데이트 흐름은 DSA의 검증된 WiX 도구 구조를 재사용한다. 모든 배포물은 Apache-2.0과
함께 배포할 수 있는 구성 요소만 포함한다.

### NFR-5 UI 표면 (`Draft`)

Rivet의 모든 UI 컴포넌트는 Appbar처럼 브라우저 창 표면의 일부로 그리고 입력을 받는다.

- 수용 기준: Rivet은 UI를 위해 별도 최상위 창, 소유 팝업, 자식 창을 만들지 않는다. 모든 컴포넌트는 브라우저
  창의 DirectComposition visual이다.
- 수용 기준: 창 이동, 크기 변경, 최대화, 복원, 스냅, 모니터 사이 DPI 변경 중과 뒤에 모든 컴포넌트가 브라우저
  레이아웃과 1픽셀 이내로 맞는다.
- 수용 기준: 글자 입력 중에도 브라우저 창이 활성 상태로 그려지고 포커스가 브라우저 창에 있다.
- 수용 기준: 글자 입력 컴포넌트에서 한국어 IME 조합 글자가 입력 위치에 그려지고 후보 창이 커서 옆에 뜬다.
  복사, 붙여넣기, 선택, 실행 취소가 동작한다.
- 수용 기준: 브라우저가 가진 동작(주소 열기, 뒤로, 앞으로, 새로 고침, 주소 읽기)은 브라우저 함수로 수행한다.

## 3. 프로토콜 요구사항

### PR-1 로컬 제어 채널 (`Agreed`)

프레임, 런타임, CLI는 하나의 버전 있는 로컬 제어 프로토콜을 쓴다. 메시지 정의는 한 곳에 두고 Rust
타입과 코덱을 생성한다.

- 수용 기준: 프로토콜 버전이나 스키마 해시가 다르면 연결을 거부하고 양쪽 버전을 보고한다.
- 수용 기준: 같은 벡터를 CLI와 런타임이 같은 바이트열로 인코딩하고 디코딩한다.

### PR-2 Ember 동기화 계약 (`Draft`)

Rivet은 Ember와 사용자 설정, 작업 공간, 클라이언트 상태를 주고받는 버전 있는 계약을 가진다.

- 수용 기준: 설정 문서의 스키마 버전이 다르면 데이터 손실 없이 호환 여부를 보고한다.
- 수용 기준: Ember가 보낸 설정은 사용자와 클라이언트 식별자로 범위가 제한된다.

### PR-3 Ember 원격 브라우저 계약 (`Draft`)

Rivet은 Ember의 컴퓨터 선택과 egress 정책을 받아, 선택된 컴퓨터의 Rivet 호스트로 브라우저 작업을
라우팅한다.

- 수용 기준: 제어 연결은 인증된 Ember 컴퓨터에만 열리고, 연결이 끊기면 열린 권한을 정리한다.
- 수용 기준: 원격 렌더링을 요청하지 않은 브라우저 처리에는 프레임 스트림을 만들지 않는다.

## 4. 수동 확인 목록

- FR-2: Windows 11에서 DPI 변경, 다중 모니터, 한국어 IME, 권한 창, 다운로드, 전체화면, 드래그앤드롭.
- FR-5: visible과 hidden 세션에서 같은 로그인된 사이트의 탐색과 에이전트 작업.
- FR-6: 두 물리 데스크톱 클라이언트 사이의 설정 및 작업 공간 전환.
- FR-7: Ember 서버와 egress 컴퓨터가 다른 실제 네트워크에 있을 때의 IP와 로컬 네트워크 접근.
